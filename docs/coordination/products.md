# products (sBestSets + sFavorites + eb-product-card) — координация

Три связанные задачи в одном заходе, потому что `sBestSets` (`384:633`,
«Лучшие наборы белья») и `sFavorites` (`428:10`, «Самые любимые модели»)
делят один и тот же компонент карточки товара (спека `669:3403 Card`).

## Заявки координатору (общие файлы, сам не трогал)

1. **Подключить `+ebProductCard` в `mixin-wrap.pug`.**
   Компонент — НОВЫЕ файлы `source/pug/blocks/mixin-wrap/components/eb-product-card.pug`
   + `eb-product-card.scss`, конфликта на диске с чужой работой нет. Но
   `mixin-wrap.pug` — общий файл (в списке §7.2 `PLAN.md`), трогать его вне
   роли координатора нельзя. Нужна одна строка:
   ```pug
   include components/eb-product-card.pug
   ```
   рядом с остальными `include components/*.pug`. До этой правки
   `+ebProductCard` доступен только тем страницам, что явно делают
   `include ../mixin-wrap/components/eb-product-card.pug` сами (так и
   сделано в `_sBestSets.pug` / `_sFavorites.pug` — оба блока включают файл
   напрямую, поэтому dev-стенды и будущая `index.pug` (после того как её
   подключит координатор) отрендерятся корректно уже сейчас; проверено
   сборкой — `+ebProductCard` резолвится).

2. **Подключить `js/best-sets.js` в боевой `allcjs()`.**
   `source/pug/layout/js-css.pug` — тоже `layout/*`, вне границ задачи.
   Нужна одна строка в `allcjs()`, рядом с остальными `script(src=...)`
   блоков:
   ```pug
   script(src=`js/best-sets.js`)
   ```
   Файл самодостаточен (`document.querySelectorAll('.sBestSets')`, ничего не
   делает, если блока на странице нет) — подключать можно всем страницам,
   как и остальные скрипты блоков. Пока для QA скрипт подключён напрямую в
   `source/pug/pages/dev/sBestSets.pug` (`block scripts`).

## Компонент `+ebProductCard(product)`

`source/pug/blocks/mixin-wrap/components/eb-product-card.pug` /
`eb-product-card.scss`. Форма данных:

```js
{
  image, imageAlt,
  badge: { type: 'new' | 'sale', text },   // необязательно
  swatch: { color, count },                // color — hex-строка из данных,
                                            // count — необязательно
  title, price, oldPrice                   // oldPrice — необязательно
}
```

- Фото — `aspect-ratio: 440 / 550` (пропорция карточки из макета) +
  `object-fit: cover`, бокс на фоне `var(--eb-surface)`.
- Бейдж «New»/«−16%» — слева сверху. Тип бейджа (`new`/`sale`) решает не
  bemto-модификатор (`"--" + mod`), а отдельный литеральный класс
  `is-new`/`is-sale`: оба значения приходят из данных (JSON), а грабля этого
  проекта («bemto сам достраивает базовый класс из модификатора») бьёт
  именно на runtime-строках с `--` — с `is-new`/`is-sale` дублирования
  класса нет, `html-validate` (`no-dup-class`) чист.
- Свотч — кружок 24px + «+N». Цвет свотча — контент из данных (снят из
  Figma: реальные значения `#2C2B2B` и `#F5E8D9`, оба совпадают с уже
  существующими токенами `--eb-ink`/`--eb-beige`, но хранятся в JSON как
  свежий hex, а не имя токена — свотч может прийти с бэкенда с произвольным
  цветом). Инлайновый `style="background-color:…"` на дочернем элементе
  разрешён граблей проекта («цвет свотча — контент»); в `eb-product-card.scss`
  ноль литеральных цветов, только токены.
- Название — `-webkit-line-clamp: 2`, а не фиксированная высота (грабля
  «карточки не должны разъезжаться по высоте при разной длине названия»).
- Старая цена — `var(--eb-text-soft)` (65%), не 35% из макета: тот же
  паттерн, что уже решён в `eb-hotspot__card-title` (`docs/coordination/
  sFitting.md`) — контраст 35% = 2.05, ниже порога 4.5, axe валит как
  serious.
- Карточка — `height: 100%`, `flex-direction: column`, без `flex: 1 0 0` на
  самой карточке и без фиксированных высот — на мобильном высота по
  контенту (грабля `flex: 1 0 0` уже назначена этому компоненту в
  `PLAN.md` §3.1).

## sBestSets — табы

WAI-ARIA tabs pattern: все 5 панелей (наборов по 4 карточки) лежат в DOM
сразу — `role="tablist"`/`role="tab"`/`role="tabpanel"`, активная кнопка —
`aria-selected="true"` + `tabindex="0"`, остальные `aria-selected="false"` +
`tabindex="-1"`; неактивные панели скрыты нативным `hidden` (не «баг видимости
в DOM», а штатное поведение таб-паттерна — `hidden` убирает узел и из
accessibility-дерева). Переключение — `source/js/best-sets.js`: клик и
клавиатура (`ArrowLeft/Right/Up/Down`, `Home`, `End`, автоактивация по
стрелке — как в референсном WAI-ARIA APG tabs example).

Проверено **замером**, не на глаз (Playwright, см. отчёт координатору):
клик по второму табу меняет `aria-selected` на кнопках, `hidden` на
панелях (ровно 1 видимая до и после), и реальный список заголовков карточек
(`.eb-product-card__title`) — 4 разных названия до, 4 других после.
Клавиатура (`ArrowRight` с фокуса на первом табе) даёт тот же результат и
переносит фокус на новую активную кнопку.

## Компромиссы / отклонения от буквального макета

- **Контент остальных 4 табов — не из макета.** В `384:633` реальные карточки
  есть только для активного таба «Идеально для большой груди» (4 товара).
  Остальные четыре таба («Невидимое под одеждой», «Без косточек», «Для
  спорта», «Для дома») собраны из ТОГО ЖЕ набора 4 товаров в другом порядке
  (см. `_note` в `source/pug/data/sBestSets.json`) — чтобы переключение
  можно было проверить функционально (реальная смена списка карточек), а не
  только визуально (тот же контент). Если у заказчика есть реальный каталог
  под каждый фильтр — данные надо заменить контент-менеджеру/бэкенду, разметка
  и компонент этого не требуют.
- **Фото — не оригинальные ассеты фотостудии, а экспорт из Figma.** Скачаны
  через `download_assets` по каждому узлу карточки отдельно (не общий экспорт
  секции — так надёжно сопоставляется фото ↔ товар), сконвертированы в JPEG
  (`sips`, качество 82, ширина 880px = 2× от 440px карточки) тем же способом,
  что уже делал `sFitting` (`docs/coordination/sFitting.md`) — оставлен JPEG,
  а не WebP, для консистентности с прецедентом; `<picture>`/`webp` можно
  добавить в финальном рефакторинге сразу для всех блоков разом.
- **`mix-blend-multiply` и точечные ручные кропы фото в макете не
  воспроизведены** — часть карточек в Figma (`Maribel`, `Full Cup Side
  Support Bra`) используют `mix-blend-mode: multiply` поверх фонового цвета
  и/или руками подобранный кроп (`top/left` в %, `height: 119–124%`) для
  конкретного кадра. Здесь — единый `object-fit: cover` на общем
  `aspect-ratio` для ВСЕХ карточек компонента: сохраняет пропорции без
  искажений на любом фото, но не воспроизводит именно эти ручные
  microadjustments. Визуально расхождение минимальное (см. скриншот-сверку),
  сочтено осознанным упрощением ради единого компонента на много карточек.
- **Свотч — не то же самое, что маленький SVG-кружок из Figma.** В макете
  кружки свотчей — отдельные векторные `<circle>` (`Ellipse 32`/`33`,
  `fill="#2C2B2B"`/`"#F5E8D9"`). Здесь — `div` с инлайновым
  `background-color` из данных (см. выше, почему это разрешено). Визуально
  идентично, но не иконка/SVG — обосновано тем, что это будет содержимое
  каталога (цвет товара), а не декоративный ассет.
- **Мобильная раскладка** — 2 колонки (по метаданным мобильного макета
  `692:1129` → `726:377`/`726:551`: карточки 170px, gap 5px по горизонтали,
  20px по вертикали), 4 колонки от `md` (768px) и шире — совпадает с
  desktop-раскладкой макета (`384:633`/`428:10`: 440px карточка, gap 10px).
- **Табы на мобиле — горизонтальный скролл, не перенос строк.** Сумма
  ширины кнопок в макете (`726:378`, 780px) больше ширины мобильной секции
  (345px) — решено как горизонтальная прокрутка (`overflow-x: auto`,
  скрытый скроллбар), а не `flex-wrap`, чтоббы не терять высоту 52px и не
  сжимать подписи табов.
