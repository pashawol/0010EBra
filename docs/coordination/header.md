# header / top-nav — координация

Шапка сайта (`318:527` desktop / `777:28` mobile) + попап каталога (`607:2934`
level1 / `607:3054` level2, hover-спека `609:4165`), файл `Wu9ocMTTTZvyFYbVm9Pz2D`.

## Заявки координатору (общие файлы, сам не трогал)

1. **`source/pug/layout/js-css.pug` — нужно подключить `source/js/header.js`.**
   Своя интерактивность попапа (открытие/закрытие, focus trap, Escape,
   hover/focus-переключение level2, мобильный drill-down) живёт в
   `source/js/header.js` (vanilla, без jQuery). Файл уже собирается в
   `public/js/header.js` автоматически (`source/js/**/*.js` копируется как
   есть), но подключения `<script src="js/header.js">` в `+allcjs()`
   (`js-css.pug`) нет — сам этот файл не правлю (не моя зона). На dev-странице
   (`source/pug/pages/dev/header.pug`) подключаю его точечно в `block scripts`,
   так что там всё уже работает — на реальных страницах (`index.pug`,
   `00-modal.pug`) появится, как только `+allcjs()` подключит файл.

2. **[РЕШЕНО координатором] `<base>` для `public/dev/*.html`.** Страница
   лежит в подпапке, относительные `css/js` из `+allcss()/+allcjs()`
   промахивались на уровень (404, страница без стилей). Координатор завёл
   `block base` в `main.pug` — моя `source/pug/pages/dev/header.pug`
   переопределяет его как `base(href="../")`. Готово, зелёное
   (`npx html-validate public/dev/header.html` — 0 ошибок).

## Найденная, но не своя грабля — `+icon()` не поддерживает chained-класс

`source/pug/blocks/mixin-wrap/components/icon.pug` рендерит
`svg(class="icon icon-" + name + ' ' + mod)` **без** `&attributes(attributes)`.
Значит паттерн `+icon('arrow-right').eb-hotspot__card-icon` (используется в
`eb-ui.pug` → `ebHotspot`, и, судя по всему, задуман как рабочий) **молча
теряет** дополнительный класс — проверено на собранном `public/index.html`:
`<svg class="icon icon-arrow-right ">` без `eb-hotspot__card-icon`. Это не
ломает вёрстку (визуально `.icon-arrow-right` уже стилизован через
`_base.scss`), но любой блок, который расчитывает на такой chain для
кастомного размера/цвета иконки, ничего не получит. В своих миксинах
(`catalogItem`/`catalogPanel`) используется безопасный второй параметр
`+icon(name, 'literal-class')` — он просто конкатенируется строкой, работает.
Не правлю `eb-ui.pug`/`icon.pug` (не моя зона) — оставляю как находку.

## Компромиссы / отклонения от буквального макета

- **Фото трёх раскрывающихся категорий (Нижнее бельё / Купальники / Домашняя
  одежда) — плейсхолдеры** из уже существующих ассетов других блоков
  (`img/sAudience/card-asymmetry.jpg`, `img/sHero/hero-slide-1.jpg`,
  `img/sGifts/lingerie.png`). Реальная предметная съёмка каталога в макете не
  экспортирована отдельно по категориям — при получении реальных фото просто
  меняются пути в `source/pug/data/header.json` (`catalog.categories[].children.image`).
- **Мобильный бургер — единственный триггер каталога.** В ноде `777:28`
  (metadata `Frame 816`) нет отдельной пилюли «Каталог», только burger +
  4 иконки — на десктопе (`499:1118`) пилюля есть отдельно. Соответственно
  бургер и десктопная пилюля оба несут `data-catalog-open` и открывают один
  и тот же `#catalogModal`. **Общее мобильное меню (3 экрана, `777:2` /
  `777:1466` / `777:1584`) — НЕ часть этой задачи** (по `docs/PLAN.md` §3 это
  отдельный пункт инвентаря блоков, а не подпункт «шапка»); бургер здесь не
  открывает то меню, только каталог.
- **Hover-спека `609:4165`**: в макете при hover списка категорий часть
  пунктов визуально приглушена (не активная категория). Не смог однозначно
  восстановить точное правило приглушения только по скриншоту (какой именно
  триггер даёт именно такое разбиение). Реализовано: hover/focus по пункту
  С подменю переключает активную level2-панель и подсвечивает сам пункт цветом
  `--eb-accent` (см. `.catalog-modal__item-link:hover, &.--active`); пункты
  без подменю (`Аксессуары`, `По виду груди`, `Спортивное/Эротическое бельё`,
  `Одежда для сна`, `Пляжная одежда`) — обычные ссылки-заглушки без
  переключения панели. Если ревизор сверит с макетом и найдёт другое точное
  поведение затемнения — донастроить в `.catalog-modal__item-link` через тот
  же `--active`/`:hover`.
- **Десктопный `.catalog-modal__dialog`** — центрированная карточка
  `min(100%, 920px)` вместо оригинального asko-паттерна (широкий dropdown под
  хедером на всю ширину контента). У нас в макете (`607:2934`/`607:3054`)
  панель визуально ближе к компактному диалогу слева-сверху с блюром фона —
  сделано ближе к этому, а не к asko-варианту (тот был образцом ТОЛЬКО для
  механики list/panel + drill-down, не для геометрии).
- **Найден и исправлен в процессе QA (не в финальной сдаче, но стоит
  зафиксировать):** оборачивание `.top-nav__inner` в Bootstrap `.container`
  сначала увело burger+каталог-группу от истинного левого края к центру узкого
  контейнера, а при `justify-content: space-between` с 3 flex-item (burger,
  catalog-btn, `nav.actions` — лого `position:absolute` из раскладки не
  участвует) средний элемент (catalog-btn) вставал на 50% ширины бара и
  налезал на центрированное лого. Пофикшено: (1) `.container` заменён на
  паддинг через `var(--eb-gutter)`, (2) burger+catalog-btn сгруппированы в
  `.top-nav__start`, оставляя ровно 2 flex-item по бокам от лого. Скриншот-
  сверка после фикса — чисто, коллизии нет.
