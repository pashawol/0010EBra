# Тестирование — 0010EBra

Стартер приехал с готовым «Class B» харнесом. Ниже — что чем проверяется и что считается «готово».

## Слои

| Слой | Инструмент | Команда | Что ловит |
|---|---|---|---|
| Unit / рендер блоков | Vitest + node-html-parser | `npm test` | блок рендерится, нужные узлы/классы/атрибуты на месте, snapshot |
| Fuzz | Vitest + fast-check | `npm test` (`tests/fuzz.test.js`) | Pug-миксины не падают на произвольных данных |
| Мутационное | Stryker (только `lib/utils.js`) | `npm run test:mutation` | качество тестов утилит |
| Разметка | html-validate | `npm run validate:html` | невалидный HTML в `public/` (входит в `build`) |
| Стили | Stylelint | `npm run lint:css` | хардкод цветов, дубли селекторов/свойств |
| JS | Biome | `npm run lint:js` | стиль/ошибки JS |
| E2E: оверфлоу | Playwright | `npm run test:e2e` | горизонтальный скролл на 375/768/1280 |
| E2E: a11y | Playwright + axe-core | `npm run test:e2e` | critical/serious нарушения доступности |

`npm run test:e2e` сам делает `npm run build` и поднимает `public/` на `http://localhost:5180` — отдельно запускать сборку не нужно.

## Как тестируется блок

Хелпер `tests/helpers/render-block.js` рендерит блок изолированно через `pug.render()` с правильным `basedir`. Поддерживает оба соглашения имён: `_<name>.pug` и `<name>.pug`.

```js
import { renderBlock } from './helpers/render-block.js'
import { parse } from 'node-html-parser'

const root = parse(renderBlock('sHero'))
expect(root.querySelectorAll('.sHero__item').length).toBeGreaterThan(0)
```

Опции: `renderBlock('name', { call: '+name(data)' })` — переопределить вызов миксина, `{ file }` — путь include.

**Правило: каждый новый блок получает как минимум один тест** — «рендерится без исключения» + проверка ключевых узлов из макета.

## Списки страниц в e2e

`tests/e2e/layout.spec.js` и `a11y.spec.js` содержат захардкоженный `PAGES` (`/`, `/00-modal.html`). При добавлении страницы — **дописать её в оба списка**, иначе она не проверяется вообще.

## Отключение axe-правил

В `a11y.spec.js` есть `ALLOWED_RULES` (сейчас `['list']` — демо-брейдкрамб на Swiper). Добавлять правило туда можно **только с письменной причиной в комментарии рядом**, как сделано для существующих. Дефолт — чинить разметку, а не глушить правило.

## Definition of Done для блока

Блок считается сданным, только когда всё это зелёное:

1. `npm test && npm run lint` — зелёные.
2. `npm run validate:html` — без ошибок.
3. `npm run test:e2e` — нет горизонтального оверфлоу на 375/768/1280, нет critical/serious axe.
4. **Скриншот-сверка с макетом** на 375/768/1280 — расхождений по композиции/размерам/цветам нет.
5. **Видимость:** «есть в DOM, но не видно на скриншоте = БАГ, не готово».
6. Ни одного литерального цвета в SCSS блока — всё через токены.

Пункты 1–3 — механика, пункты 4–6 гоняет ревизор по `~/.claude/verstka-delivery.md`.

## Отладка красного теста

Любой failure → сначала ресерч (глобальное правило `~/.claude/CLAUDE.md`): точный текст ошибки + название механизма в WebSearch, 2–3 запроса под разными углами, потом гипотезы, потом проверка на реальном окружении. Не строить решение с нуля из головы.

После любого инцидента (красный тест, находка ревизора CONFIRMED, переделка по замечанию Pavel) — вызвать скилл `грабля`, не дожидаясь напоминания.
