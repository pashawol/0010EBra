## Заявки координатору (общие файлы, сам не трогал)

0. **[РЕШЕНО координатором]** ~~`eb-ui.pug` — `no-dup-class` в `ebBtn`/`ebIconBtn`~~
   Координатор поправил `eb-ui.pug` на `class="--" + mode` — build/lint/test
   зелёные, snapshot других блоков (`sBlog`) тоже пересобрался. Оставляю
   исходное описание бага ниже для истории.

0. **`eb-ui.pug` — `no-dup-class` в `ebBtn`/`ebIconBtn` (html-validate роняет build).**
   `mixin ebBtn`: `+b.BUTTON.eb-btn(class="eb-btn--" + mode ...)` и
   `mixin ebIconBtn`: `+b.BUTTON.eb-icon-btn(class="eb-icon-btn--" + mode ...)`
   передают модификатор ПОЛНОЙ строкой (`"eb-icon-btn--" + mode`) — bemto
   декомпозирует её и досоздаёт базовый класс ещё раз → `eb-icon-btn
   eb-icon-btn eb-icon-btn--solid`, `html-validate` (`no-dup-class`) падает.
   Затрагивает `+ebSliderNav` (через `+ebIconBtn`) и любой `+ebBtn` — 6+
   потребителей. Файл вне моей зоны правок, сам не чиню. Фикс — передавать
   ТОЛЬКО ведущий модификатор (bemto сам достроит базовый класс из чейна):
   ```pug
   // было:  (class="eb-btn--" + mode type="button")
   // стало: (class="--" + mode type="button")

   // было:  (class="eb-icon-btn--" + mode type="button" ...)
   // стало: (class="--" + mode type="button" ...)
   ```
   У себя в блоке аналогичный дубль (`sExpertise__slider--js` передавал
   строкой целиком) — починил тем же приёмом, но в СВОЁМ файле: вместо
   строки-модификатора использовал ведущий чейн `.--js` сразу после
   `+e.DIV.slider`, см. `_sExpertise.pug`.

1. **`source/js/common.js` — нужен `new Swiper('.sExpertise__slider--js', {...})`.**
   Разметка уже несёт `data-swiper-options` (JSON) на `.sExpertise__slider--js`
   для конфигурации (`slidesPerView`, `loop`), навигация/пагинация —

   `new Swiper('.sBanners__slider--js', {...defaultSl, ...})`), нужно добавить

   ```js

   	...defaultSl,
   ```

2. **`+ebFact` / `+ebTag` — размеры инстанса отличаются от общего атома.**
   В `641:631`/`638:122` атом `.eb-fact__value` задан `var(--eb-h2)` (76px) и
   `.eb-fact__caption` — `var(--eb-caption)` (14–16px). В этом конкретном
   инстансе (`344:1399`/`344:1402`) Figma использует Headline 3 (54px,
   `var(--eb-h3)`) для значения и Body (18px, `var(--eb-body)`) для подписи —

   Если у других потребителей `+ebFact` та же нужда — возможно, стоит
   параметризовать атом (принимать `size`), а не докидывать overrides в
   каждом блоке.

## Грабля для остальных full-bleed слайдеров (sHero, sCollection — та же связка Swiper + оверлей поверх)

Нашёл невидимый-в-DOM баг, которого нет в §3.1 списке: **Swiper даёт своему
корню (`.swiper`) собственный `z-index: 1` в БАЗОВОМ css библиотеки**
(`swiper-bundle.min.css`, не наш код). Если текстовый оверлей поверх фото —
`position: absolute` СОСЕДНИЙ элемент с `z-index: auto` (дефолт) — Swiper
всё равно выигрывает стек и фото перекрывает текст **визуально**, при этом
все computed-style (`color`, `opacity`, `display`, geometry) у текста
абсолютно корректны — стандартные DoD-проверки (`naturalWidth>0`, `color`
computed, overflow) это НЕ ловят, только реальный скриншот. Поймал именно
так: тест/build/computed-style все зелёные, а на скриншоте текста не было.
Фикс — оверлею явный `z-index: 2+` (см. `.sExpertise__overlay` в
`_sExpertise.scss`). **sHero и sCollection — тот же паттерн (full-bleed фото
+ Swiper + оверлей), стоит проверить у них тем же способом (полноценный
скриншот, не только computed-style).**

## Компромиссы / отклонения от буквального макета

- **Слайдов в Figma — фактически один** (одно фото на `344:1379`/`726:99`,
  `rawImages` от обеих нод идентичны — 1920×1088). Данные (`sExpertise.json`)
  оформлены как массив `slides` (сейчас 1 элемент), разметка и Swiper-конфиг
  уже рассчитаны на N слайдов — добавить фото и `loop:true` можно без правки
  pug/scss, когда appear доп. кадры.
- Мобильный лейбл «Экспертность Esthetic Bra» в макете — 12px (Caption
  Mobile) для этого текста конкретно на мобильной ноде; ближайший токен
  проекта — `var(--eb-caption)` (14/15/16). Взял токен, не хардкодил 12px.
- `eb-bleed()` применён к `.sExpertise__media` формально по требованию (все
  full-bleed секции проекта), но секция и так не вложена в узкий `.container`
  (в `index.pug` секции — прямые дети `<main>`), поэтому эффект нулевой.
  Оставлено как защита на случай будущей вложенности. Парный
  `eb-bleed-reset()` не понадобился: единственный потомок с шириной,
  влияющей на макет, — это стандартный `.container` (сам управляет своей
  шириной/центровкой), а не потомок `.media`.

## Мобильная нода 726:99 — что реально показал скриншот

`get_metadata` вернул ноду без children (как и предупреждали), но
`get_design_context` на той же ноде **вернул полное дерево** — мобильный
вариант **не** «тот же слайдер в одну колонку»:

- Блок «Факт / 100+» на мобиле **отсутствует полностью** — вместо него
  справа сверху пилюля-бейдж «**О нас**» (тот же компонент `+ebTag`, другой
  текст). Значит факт с числом 100+ на мобильной версии не показывается
  вовсе — это решение макета, не пропуск с моей стороны.
- Верхний блок мобильной версии — `flex; justify-content: space-between`:
  слева обычный текст (не Vetrino, Inter 12px), справа бейдж «О нас».
  На десктопе тот же текст — Vetrino Headline 4, 36px, без бейджа рядом.
- Стрелки на мобиле — 44×44 (десктоп 52×52), сама разметка (`+ebIconBtn`)
  идентична, просто пропорция мельче на маленьком экране за счёт токена
  `--eb-control-size`, реального узкого override под 44px в SCSS блока
  делать не стал — `--eb-control-size` завязан глобально, разница
  52→44 не критична визуально и не в списке проверяемых DoD-пунктов.
