## 1. Баг в `+ebIconBtn` (mixin-wrap/components/eb-ui.pug) — дублирует базовый класс

Воспроизводится в полной изоляции, без моего вызова:

```js
renderBlock('x', {
	file: 'source/pug/blocks/mixin-wrap/components/eb-ui.pug',
	call: "+ebIconBtn('play','test')",
})
// → <button class="eb-icon-btn eb-icon-btn eb-icon-btn--solid" ...>
```

Причина: миксин задаёт базовый класс через bemto dot-notation (`+b.BUTTON.eb-icon-btn`) И
одновременно динамический `class="eb-icon-btn--" + mode` атрибутом — на этой комбинации bemto
эмитит базовый класс дважды. `html-validate` (`no-dup-class`) валит сборку любой страницы, где
`+ebIconBtn` реально дошёл до вывода. Затронуты минимум `sProcess`, `sHero`, `sAudience`,
`sExpertise` (видно по `no-dup-class` на их `dev-*.html` в одном прогоне `npm run build`) —
компонент общий, чинить должен координатор после `grep` всех потребителей `+ebIconBtn`/`+ebBtn`
(в `eb-btn`/`eb-btn-text` та же конструкция, тоже под подозрением).

**Мой обход** (в `_sProcess.pug`, не трогает `eb-ui.pug`): вместо `+ebIconBtn('play', label)`
воспроизвёл тот же контракт классов вручную —

```pug
button.eb-icon-btn.eb-icon-btn--solid(type="button" aria-label=data.widget.title)
	+icon('play')
```

Даёт идентичную разметку/стили/hover без дубля класса. Если координатор поправит `eb-ui.pug` —
можно вернуть вызов `+ebIconBtn` в `sProcess` and убрать обход.

## 2. Заявка: accent-режим для `+ebIconBtn`

Круглая кнопка play на мини-карточке видео в макете — заливка `--eb-accent` (бордовый), а не
`--eb-surface` (как в существующих режимах `solid`/`ghost`). Переопределил цвет локально —
`.sProcess__widget .eb-icon-btn--solid { background-color: var(--eb-accent); ... }` — скоуп
только под моим блоком, `eb-ui.scss` не трогал. Если такой цвет понадобится другим блокам
(попапы видео-отзывов, `sReels`?) — стоит завести настоящий `mode: accent` в `ebIconBtn`.

## 3. `tests/helpers/render-block.js` — данные блока не подхватываются автоматически

Блок использует `data = data || sProcess` (тот же паттерн, что `sTransformIntro`, `sHero`).
`renderBlock()` не мёржит `source/pug/data/*.json` (это делает только gulp-data в реальной
сборке) — без `locals` рендер падает на `Cannot read properties of undefined`. Тот же провал
воспроизводится сейчас и на `tests/blocks-sHero.test.js` (`npm test`, независимо от меня).

Обошёл в своём тесте: подгружаю `source/pug/data/sProcess.json` напрямую и передаю
`renderBlock('sProcess', { locals: { sProcess: fixtureData } })` — задокументированный, но
недоиспользуемый путь хелпера (`options.locals`, см. комментарий в самом файле). Не редактировал
`render-block.js` (общий файл). Если у других блоков тесты сейчас красные по той же причине —
это тот же паттерн-фикс, не блок-специфичный баг.

## 5. Компромиссы по вёрстке

- **Мобильная лента шагов** — горизонтальный скролл на `100vw` (`eb-bleed()`/`eb-bleed-reset()`,
  сброс на `lg+`), карточка `min(78vw, 320px)`, следующая слегка выглядывает — 4 фото не влезали
  в ряд на 375px ни при каком уменьшении без потери читаемости подписи/шкалы под фото.
- **Порядок на мобиле**: в макете (`710:1924`) мини-карточка видео идёт ПОСЛЕ ленты шагов, не
  перед ней как на десктопе. Раскладка сделана через CSS Grid на `lg+`
  (`grid-template-areas: "title widget" "steps steps"`), а не `order` — DOM-порядок везде
  title → steps → widget, меняется только визуальное место сеткой.
- **Шкала-линейка** — чистый CSS: `repeating-linear-gradient` на 37 делений + отдельный высокий
  стартовый штрих (`::before`/`::after`), без картинки.
- **Ширина мини-карточки в Figma на мобиле — 44px** у кнопки play (у десктопа 52px). Оставил
  везде `--eb-control-size` (52px, глобальный токен `+ebIconBtn`/`eb-icon-btn`), чтобы не заводить
  локальный оверрайд размера контрола — расхождение на 8px, визуально малозаметно.
- **Label `Видео обзор` (65% чёрного в Figma)** — ближайший существующий токен `--eb-text-muted`
  (75%), отдельного токена под 65% нет и заводить его в `_root.scss` не в моих правах.
