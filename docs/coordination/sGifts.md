Блок «Подарочные решения» (node `483:1239` desktop / `726:675` mobile

## Заявка: вынести Banner в общий `+ebBanner`

По `docs/PLAN.md` §4 карточка-баннер — один компонент Figma (`669:3449`,
`669:3523`), используемый и здесь, и в `sPromo` (3 промо-баннера). Свёрстал
свою копию **локально**, без правки `eb-ui.pug`/`eb-ui.scss`:

- Локальный pug-миксин `sGiftsBanner(card)` в `source/pug/blocks/sGifts/_sGifts.pug`.
- Разметка: `.sGifts__card` (позиция `relative`, `overflow:hidden`,
  `border-radius: var(--eb-radius)`) → `<img class="sGifts__card-img">`
  (`object-fit:cover`, абсолютно спозиционирован) → опциональный
  `::after`-скрим-градиент (только у карточек на светлом фото) →
  `<span class="sGifts__card-caption">` поверх (шрифт `$font-family-display`,
  `var(--eb-h4)`).
- Тёмная тема (карточка сертификата) включается классом `.eb-theme--dark`,
  навешенным **на саму карточку** (не на секцию) — по прецеденту `sExpertise`
  (`.eb-theme--dark` на `+b.SECTION`). Подпись читает `var(--eb-text)`,
  доп. правил цвета не потребовалось.

**Предлагаемая сигнатура общего атома**, когда координатор будет сводить с
`sPromo`:
```pug
mixin ebBanner(image, caption, mod)
	+b.eb-banner(class="eb-banner--" + mod)&attributes(attributes)
		+img(image).eb-banner__img
		+e.SPAN.caption!= caption
```
Модификаторы, которые нужны потребителям: высота карточки (в `sGifts` — три
разных фикс-высоты 740/560/460 на lg+, в `sPromo`, по описанию плана, скорее
одна общая высота — сверить перед обобщением) и наличие/отсутствие
градиента-скрима (только у карточек на светлом фото без тёмной темы).

## Компромисс: цвет скрима под подписью

В макете у карточек «Бельё» и «Наборы» — разовые `rgba(255,255,255,.5)` и
`rgba(245,232,217,.38)` (последний — с бежевым оттенком, которого нет ни в
одном текущем токене `_root.scss`). Заводить новый токен самостоятельно не
стал (файл вне зоны блока). Использовал существующий `var(--eb-white-35)`
(альфа `.35`) для обоих скримов — для «Наборов» это почти точное совпадение
(спека `.38`), для «Белья» — заметное отличие (спека `.5`, чуть менее
прозрачный скрим в макете). Если важна точность — нужен отдельный
бежевый scrim-токен в `_root.scss` (например `--eb-scrim-warm`), правка
только у координатора.

## Переиспользование существующих атомов

- `+ebTitle` — заголовок H2 «Подарочные решения» (`data-node 472:1138`).
- `+img` — все растровые картинки (сертификат/наборы/бельё/3 аватарки),
  путь `img/sGifts/*.png` (см. ниже про формат файлов).
- Разделитель в мини-карточке — не отдельный `<img>` (в Figma это `Line 1`
  SVG-заливка), а обычный `border-left` на тексте: визуально идентично,
  без лишнего asset-запроса.

## Ассеты

Экспортированные из Figma файлы физически в формате **PNG** несмотря на
исходное расширение в API-ответе (`.jpg` в URL, реальные байты — PNG,
проверено `file`). Сохранены как `source/img/sGifts/{cert,sets,lingerie,
avatar-1,avatar-2,avatar-3}.png` — сборка (`gulp images`) принимает `png`
наравне с `jpg` (`paths.imgSource: '**/*.{jpg,jpeg,png}'`), генерирует webp
автоматически. Десктопная и мобильная ссылки на баннер-фото в Figma
(`imgBanner`/`imgBanner1`/`imgBanner2` на обеих нодах) физически ведут на
**один и тот же** файл (совпадают побайтово) — отдельных mobile-кропов не
существует, обошёлся одним набором изображений на все брейкпоинты
(`object-fit:cover` перекрывает разницу пропорций 590×740 / 345×275).

## Геометрия (desktop, lg+)

3 колонки `flex:1 0 0`, `gap: 10px`, реплицируют сетку макета (590+590+590
+ 2×10 = 1790). Высоты — фикс rem, а не % от секции (грабля из
`+ebHotspot`): карточка сертификата — опорная высота ряда `rem(740)`
(растяжение `align-items:stretch` по умолчанию у флекс-строки подтягивает
остальные колонки к этой высоте), колонки «Бельё» и «Наборы+виджет»
используют `justify-content: space-between`, чтобы получить те же отступы
280px/105px, что и в макете, без хардкода отступа.
