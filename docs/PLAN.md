## 6. GSAP: scroll-анимации

Figma motion-данных нет (`get_motion_context` → `{"nodes":[]}` на всех проверенных нодах) — **автоматически вытащить анимацию нельзя**. Но на странице `576:2` дизайнер нарисовал **раскадровку**, и она читается:

| Сцена | Кадры | Что происходит |
|---|---|---|
| Sections | `576:3`, `576:223`, `576:332`, `576:441` | базовые состояния секций |
| Transition 2 | `576:553`, `599:267`, `599:347` | 3 шага |
| Transition 3 | `599:172`, `599:176`, `602:430`, `602:517`, `602:606` | 5 шагов: «Тысячи подборов» → «Интерактивный квиз» |
| Transition 4 | `602:805`, `602:922`, `602:1035`, `602:1148` | 4 шага |
| Transition 5 | `602:1540`, `602:1769`, `602:1997`, `604:2236`, `604:2466`, `604:2696` | 6 шагов, самая длинная |

**Важно: переносить инфраструктуру не из чего.** Проверил три проекта студии: в `0041-asko` (свежий магазин) GSAP не используется вообще — там CSS-transition + точечный `IntersectionObserver`. В `0044Ceramics` и `0007Lintex` GSAP есть, но это рукописный per-page код: без `gsap.context()`, без `ScrollTrigger.matchMedia()` (мобилка через ветвления `window.innerWidth` внутри каждой функции), с ручным `ScrollTrigger.getAll().forEach(kill)` и перезапуском всех анимаций на каждый resize. `prefers-reduced-motion` не встречается ни в одном из трёх проектов. Копировать это нельзя — проектируем слой с нуля.

**Подход:** каждая сцена = отдельный ScrollTrigger-таймлайн в своём файле (`source/js/anim/transition-3.js`), кадры раскадровки = ключевые точки таймлайна, между ними интерполяция. Пины и `scrub` — по месту. Сверху — тонкая общая обёртка: `gsap.context()` на секцию (корректный cleanup), **`gsap.matchMedia()`** вместо ветвлений по `innerWidth`, единая проверка `prefers-reduced-motion`, `ScrollTrigger.refresh()` на resize вместо перезапуска сценариев.

> `ScrollTrigger.matchMedia()` устарел с GSAP 3.11 — использовать **`gsap.matchMedia()`**. (Первая редакция плана называла устаревший API; исправлено ревизией.)

**Технические грабли, которые обязаны быть закрыты в коде:**
- **Пин + Swiper.** ScrollTrigger пинит через `transform`, а `transform`/`will-change` на предке ломает `position: fixed`. Swiper двигает `.swiper-wrapper` тем же `transform` — а пинить придётся именно секции со слайдерами (`sHero`, `sExpertise`, `sCollection`). Решение по месту: `pinType: "fixed"` либо `pinReparent: true`, Swiper-контейнер изолируем от предка с `transform`.
- **Refresh после загрузки картинок.** `ScrollTrigger` считает start/end до декодирования изображений и промахивается. Нужен `ScrollTrigger.refresh()` после `decode()`/`imagesLoaded` hero-картинок, а не только на resize.
- **Цвета в JS-таймлайнах.** `declaration-strict-value` не видит JS. Анимации цвета читают значения из тех же CSS-переменных (`getComputedStyle` / `var(--accent)`), хардкод hex в таймлайне запрещён — иначе токены разъедутся между SCSS и JS.

Обязательные требования к анимациям:
- `prefers-reduced-motion: reduce` → анимации отключаются, контент сразу в финальном состоянии;
- на мобилке тяжёлые пины не вешаем (`gsap.matchMedia()`), иначе получим залипший скролл;
- анимация **не должна прятать контент навсегда**: если JS не выполнился, всё видно (стартовое состояние задаётся из JS, а не в CSS);
- верификация анимаций — **замером во времени** (позиция/opacity в нескольких точках скролла), а не одним статичным кадром.

**Открытый вопрос к Pavel** — в плане помечен как требующий решения, но работу не блокирует: раскадровка показывает ЧТО меняется, но не тайминги и не easing. Их беру на себя (стандартные `power2.out`, длительности по логике сцены) и показываю в финальном отчёте; если не попаду в задумку — правим вместе, как ты и предложил.

### 7.2. Протокол общих файлов (правка по ревизии)

`worktree`-изоляции недостаточно: она мешает агентам видеть работу друг друга. Файлы, которые гарантированно тронут ≥2 параллельных блока:

| Файл | Кто трогает |
|---|---|
| `source/pug/content.json` | почти каждый блок |
| `source/js/common.js` (Swiper-фабрика) | `sHero`, `sStory`, `sReels`, `sExpertise`, `sCollection`, `sBestSets` |
| `source/svg/*` → генерируемый `_sprite.scss` | многие |
| `_root.scss` / `_vars.scss` | любой, кто найдёт недостающий токен |
| компоненты §4 (`+hotspot`, `+productCard`, `+arrowsNav`) | по 3+ блока каждый |

Правила fan-out-агенту:
1. **Общий миксин/компонент правится не в лоб.** Нужна доработка `+hotspot` под свой кейс — делаешь bespoke-скоуп под блок и пишешь заявку в `COORDINATION.md`; глобальный компонент правит только координатор, после `grep` всех потребителей.
2. Любая правка общего файла — строка в `COORDINATION.md` + пометка «Пересоберите CSS/JS».
3. Перечитывать общий файл непосредственно перед каждым Edit — соседняя ветка могла его поменять.
4. Статус «блок готов» в общий трекер пишет **только ревизор, после факта проверки**. Дев-агент блока не имеет права предвосхищать вердикт ревизии.
5. Промпт каждого fan-out- и ревизионного агента заканчивается forcing-якорем: первое действие в ходу — вызов инструмента; текстовый ответ без вызова считается проваленным ходом (урок про статус-эхо, `~/.claude/lessons/agents.md`). Координатор перед тем как поверить отчёту блока смотрит на число вызовов инструментов, а не только на текст.

## 8. Definition of Done

Действует `docs/testing.md`. На каждый блок:

- [ ] Сборка зелёная, `html-validate` чист.
- [ ] Скриншоты на 375 / 768 / 1280 / 1920, **снятые локатором блока с `scrollIntoViewIfNeeded()`**, а не общим кадром страницы (иначе секции ниже фолда «сверяются» по неправильному кадру).
- [ ] Пиксельная сверка с макетом: цвета, отступы, кегли, **присутствуют ВСЕ элементы**.
- [ ] Каждая картинка декодируется (`naturalWidth > 0`).
- [ ] **Каждая иконка реально отрисована** — computed `fill`/`stroke`/`opacity`, отдельным пунктом от цветов: у контурной иконки `stroke` может быть срезан svgo и стать `none`, это не «другой цвет», а невидимая иконка.
- [ ] Нет горизонтального оверфлоу ни на одной ширине.
- [ ] Цвета — по computed-стилю под тему секции, не по исходнику.
- [ ] Ноль литеральных цветов в SCSS блока.
- [ ] **Переиспользование: не созданы дубли** ассетов/компонентов/миксинов. Проверяется в ревизии, а не откладывается на финальный рефакторинг — там дедуп ловится постфактум, ценой переделки.
- [ ] Глобальные правки помечены в `COORDINATION.md` + «Пересоберите».
- [ ] Есть vitest-тест на рендер блока.
- [ ] Новая страница/попап **дописана в `PAGES` обоих e2e-спеков** (`layout.spec.js` и `a11y.spec.js`) — списки захардкожены, иначе страница не проверяется вообще.

**Отдельно для попапов и мобильного меню.** Текущий `a11y.spec.js` гоняет axe по `page.goto()` — то есть закрытый попап он не проверит. На каждое интерактивное состояние нужен тест, который **сначала открывает состояние кликом по триггеру**, и только потом запускает axe, плюс проверка focus trap: `Tab` не должен уводить фокус за пределы открытого попапа.

**Анимации** верифицируются замером во времени (позиция/opacity в нескольких точках скролла), а не одним статичным кадром.

План прогнан через трёх независимых ревизоров с разными линзами. Ниже — что было найдено и исправлено. Записано, чтобы при исполнении не «починить обратно».

**Линза «техника и риски стека».** Три критичных:
1. `ScrollTrigger.matchMedia()` устарел с GSAP 3.11 — план называл устаревший API, заменено на `gsap.matchMedia()`.
2. Swiper: latest уже 14.0.7, но связка студии проверена на 12 — пиним `12.0.3`, а не «актуальную».
3. Fancybox 6 — шестой мажорный рерайт со сломанным конструктором и переименованным `Navigation`; это отдельная задача переписывания вызовов, а не «риск отката».

**Линза «процесс и грабли».** Три критичных:
1. **Порядок фаз был противоречив** — ревизия требовала мобильной сверки до того, как мобильная вёрстка сделана. Исправлено: блок = desktop + mobile в одном заходе, отдельная мобильная фаза убрана.
2. Не было протокола общих файлов при параллельном fan-out — добавлен §7.2 с `COORDINATION.md` и списком конфликтных файлов.
3. Не было forcing-якоря против статус-эха в промптах субагентов — добавлено в §7.2 п.5.
Плюс: 9 граблей из каталога движка назначены на конкретные блоки (§3.1), DoD дополнен переиспользованием, отдельной проверкой отрисовки иконок и скриншотом по локатору.

### 12.1. Главное: webp генерируется, но не используется

Сборка делает `.webp` рядом с каждым растром, а в разметке подключаются
оригиналы. Ни одного `webp` в собранном HTML нет.

Потенциал измерен точно: **оригиналы 8 608 КБ → webp 3 652 КБ, экономия
4 956 КБ (57%)**. Худшие случаи: `sHero/raw1.png` 1297→276 КБ,
`sPromo/banner-week.png` 781→142 КБ, `sPromo/banner-gift.png` 416→69 КБ.

Что делать: подключать картинки через `<picture>` с `<source type="image/webp">`
(в стартере для этого есть миксин `+pic()`), либо ввести свой атом.
Правка затрагивает разметку почти всех блоков — делать одним проходом, когда
блоки не заняты другими сессиями.

### 12.2. Осиротевшие ассеты — 1 830 КБ в 18 файлах

Не упомянуты ни в HTML, ни в CSS:
- `img/sHero/raw1.png` (1297 КБ), `raw2/raw3/raw4.png` — случайные выгрузки
  `download_assets().rawImages`, забытые после подбора нужного кадра;
- `img/sHero/hero-collection-thumb.jpg`;
- `img/footer/pay-*.svg` — оригиналы платёжных бейджей, оставленные «для
  истории»; в разметке используются растровые версии. Либо перейти на SVG
  (они легче и не мылят), либо удалить оригиналы;
- `img/example.jpg`, `img/slide-25.jpg` — демо-ассеты стартера, **уже удалены**.

`img/favicon.ico` в этот список попал ложно — он подключается через `<link>`,
а не через `img/...`, и трогать его не надо.

### 12.3. Бюджет зафиксирован тестом

`tests/e2e/perf.spec.js`: вес первого экрана, LCP и проверка, что картинке
первого экрана не поставили `loading="lazy"`. Пороги намеренно не выкручены —
