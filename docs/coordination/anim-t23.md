Animation `576:2`). `get_motion_context` на этих узлах пуст — дизайнер
нарисовал переходы покадрово, без Smart Animate. Разбор — по раскадровке +

локальные позиции/размеры вложенных фреймов на каждом шаге, а не только

## Разбор раскадровки

### Transition 2 — `#sAudience` → `#sFitting` (3 шага: `576:553`, `599:267`, `599:347`)

Кадры сами по себе выглядят почти одинаково (мозаика сверху, фото-секция
снизу) — разница нашлась в `get_metadata`, не в картинке:

| Шаг | Фон-прямоугольник `#sFitting` (Figma) |
|---|---|
| `576:553` | секция ещё целиком ниже вьюпорта (`y=1277` в кадре 1080px) — не видна |
| `599:267` | фрейм `Section 3` **1870×1030** при канвасе 1920×1080 → равномерный отступ **25px**, скруглённые углы |
| `599:347` | фрейм `Section 3` **1920×1080**, отступ **0**, углы прямые |

На **шаге 1** (более раннем, чем `576:553` — экстраполирую по разнице между
`576:553` и `599:267`) отступ **45px**. То есть по мере того, как `#sFitting`
въезжает снизу, она "распахивается" из скруглённой карточки с рамкой в
full-bleed полосу: `inset(46px round 30px)` → `inset(0 round 0)`.

**Реализация** (`anim-transition-2.js`): `clip-path` на самой секции
`#sFitting`, `scrub`-таймлайн `ScrollTrigger` (`trigger: '#sFitting'`,
`start: 'top bottom'`, `end: 'top top'`) — то есть эффект длится ровно на
пути от появления нижнего края вьюпорта до момента, когда секция встаёт на
место (совпадает с раскадровкой: на `599:347` `Section 3` уже `y=0`).
Пин не нужен — секция и так занимает своё обычное место в потоке, анимируется
только маска. Мобилка — меньшая амплитуда (`20px/16px` вместо `46px/30px`),
через `gsap.matchMedia()`.

### Transition 3 — `#sExpertise` → `#sQuiz` (5 шагов: `599:172`, `599:176`, `602:430`, `602:517`, `602:606`)

Здесь `get_metadata` дал другой результат: у всех 5 кадров фон/картинка
`img BG` и все вложенные фреймы чата **не меняют** размер/скругление —
только вертикальную позицию (`y` линейно уменьшается кадр к кадру, ровно как
при обычном скролле). Ни один элемент чата не помечен `hidden`/полупрозрачным
на "ранних" кадрах — на `602:430` (шаг 3) блок ответа ИИ-ассистента
физически присутствует в дереве узла, просто его `y` ниже границы вьюпорта.

Вывод: раскадровка Transition 3 документирует **обычный порядок раскрытия
контента при скролле** (что появляется в кадре первым/вторым/третьим), а не
собственный motion-эффект внутри чата. Это соответствует прямому решению
заказчика (`docs/PLAN.md` §1.1, зафиксировано также в
`docs/coordination/sQuiz.md`): квиз — **статичная вёрстка**, без анимации
появления отдельных сообщений и без имитации набора текста. Пятишаговый
reveal реплика-за-репликой был бы ровно такой имитацией — не стал его делать.

**Что реализовано как сама сцена перехода** (`anim-transition-3.js`):

1. **Уходящая сторона** — `.sExpertise__overlay` (заголовок/факт/навигация
   слайдера) плавно тускнеет и слегка уменьшается (`scale 1→0.94`,
   `opacity 1→0.45` на десктопе, мягче на мобиле), пока `#sExpertise`
   покидает вьюпорт. `scrub`, `trigger: '#sExpertise'`,
   `start: 'bottom bottom'`, `end: 'bottom top'`.
2. **Приходящая сторона** — `.sQuiz__chat` и `.sQuiz__panel` появляются
   **одним** `fromTo` (autoAlpha+y, `stagger: 0.15` между двумя этими
   блоками, не между отдельными репликами внутри чата), `once: true` при
   входе `#sQuiz` в кадр (`start: 'top 80%'`). Заголовок `.sQuiz__title` уже
   есть класс `.eb-title` — его revealOnEnter делает сам `anim.js`, второй раз
   не анимирую (не дублирую).

## Тайминги/easing (не заданы в макете, беру на себя)

- Transition 2: `scrub: 0.3` (лёгкое сглаживание "хвоста", основной прогресс —
  жёстко от скролла, `ease: 'none'` в самом tween) — иначе clip-path либо
  дёргается либо ощущается "отвязанным" от скролла.
- Transition 3 exit: тот же `scrub: 0.3`, `ease: 'none'`.
- Transition 3 entrance: `duration: 0.8`, `ease: 'power2.out'` — **специально
  совпадает** с параметрами `revealOnEnter` в `anim.js`, чтобы вход `#sQuiz`
  визуально не отличался по характеру от reveal остальных секций сайта.

## Проверено (числами, не одним скриншотом)

`page.addScriptTag({ url })` (уже собраны gulp'ом в `public/js/`, layout не
трогал):

- **Transition 2**, скролл в 4 точках относительно верха `#sFitting`
  (-900/-400/-50/+200px): `clip-path` меняется
  `inset(46px round 30px)` → `inset(20.45px round 13.34px)` →
  `inset(2.56px round 1.67px)` → `inset(0px)` — монотонно к нулю, совпадает

- **Transition 3**, скролл в 5 точках от низа `#sExpertise` до верха `#sQuiz`:
  `.sExpertise__overlay` opacity `0.82→0.48→0.45`, `scale` `0.98→0.943→0.94`;
  `.sQuiz__chat`/`.sQuiz__panel` opacity `0.94/0.81→1/1`, `translateY`
  `1.8px/6px→0/0` — числа реально меняются по ходу скролла, не статичны.
- **`prefers-reduced-motion: reduce`**: `#sFitting` `clip-path: none`,
  `.sExpertise__overlay`/`.sQuiz__chat`/`.sQuiz__panel` — `opacity: 1`,
  `visibility: visible`, `clip-path: none` — ничего не остаётся навсегда
  скрытым/трансформированным.
- **Swiper на `#sExpertise` после подключения сцен**: `realIndex` меняется
  `0 → 1` по клику next — сцена не ловит скролл-пин на секции со слайдером
  (пин вообще не используется ни в одной из двух сцен), конфликта
  transform/Swiper нет.
- `npm run build` — exit 0 (единственная строка с "error" в логе —
  предсуществующий `postcss-svgo` SvgoParserError на `custom-bootstrap.css`,

## Компромиссы

- Точные px/радиусы Transition 2 (46/30 → 0) взяты из соотношения размеров
  фонового прямоугольника в Figma-метаданных, не из точного motion-спека
  (его нет) — компромисс осознан, ширины/радиусы можно скорректировать одной
  правкой констант в начале `buildScene()`.
- Transition 3 сознательно НЕ анимирует реплики поштучно — см. разбор выше;
  если заказчик всё же хочет реплика-за-репликой reveal, это отдельное
  решение, которое стоит явно переподтвердить (сейчас оно прямо запрещено
  зафиксированным интейком).
