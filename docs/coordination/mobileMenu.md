# Координация — mobileMenu

Мобильное меню, 3 экрана drill-down: `777:2` (уровень 1), `777:1466` («Купальники» —
шаблон уровня 2 «Каталог», переиспользуется под все категории), `777:1584` («Для вас»,
уровень 2). Логика — по образцу `.catalog-modal` из `0041-asko` (`common.js` +
`JSCCommon.js`), переписана на vanilla JS без jQuery (`source/js/mobile-menu.js`).

Правил только свои файлы (`source/pug/blocks/mobileMenu/*`, `source/pug/data/mobileMenu.json`,
`source/js/mobile-menu.js`, `source/pug/pages/dev/mobile-menu.pug`,
`tests/blocks-mobileMenu.test.js`, `source/img/mobileMenu/*`, этот файл). Общие файлы не
трогал — заявки ниже.

## 1. Заявка: подключить `js/mobile-menu.js` и триггер в шапке

Меню открывается любым элементом с `[data-mobile-menu-toggle]` — компонент ничего не
знает о разметке шапки, контракт целиком на атрибуте. Нужно от координатора/агента шапки:

1. Добавить `script(src="js/mobile-menu.js")` в `+allcjs()` (`source/pug/layout/js-css.pug`)
   рядом с `common.js`/`JSCCommon.js` — я не трогал этот файл (общий, в списке запрещённых).
2. Повесить `data-mobile-menu-toggle` на реальную кнопку-бургер в `top-nav`/`header`
   (`.d-lg-none` toggle) — это их файл, я не могу сам это сделать.
3. Убедиться, что `+mobileMenu()` вызывается один раз на странице (в `index.pug`, рядом с
   `+modal`/`+parts('footer')`) — тоже не мой файл.

Компонент полностью самодостаточен и протестирован независимо (dev-стенд ниже) — после
трёх правок выше интеграция должна заработать без доработок с моей стороны.

## 2. Баг в общем `source/pug/layout/js-css.pug` / `main.pug`: относительные пути ассетов

`+allcss()`/`+allcjs()` и `img(src='img/favicon.ico', ...)` в `main.pug` используют пути
**без ведущего слэша** (`css/main.min.css`, `libs/...`, `img/favicon.ico`). Это работает
только для страниц, скомпилированных в корень `public/` (как `index.html`,
`00-modal.html`). Любая страница глубже (у меня — `source/pug/pages/dev/mobile-menu.pug` →
`public/dev/mobile-menu.html`, ТЗ явно требует этот путь) резолвит эти пути относительно
своей директории — `public/dev/css/main.min.css` (404), стили **молча** не грузятся,
страница рендерится default user-agent styles без единой ошибки в консоли, кроме сетевых
404. Тот же эффект будет у любого будущего `dev/*`/вложенного дев-стенда другого блока.

**Не мой файл — не правил.** Обошёл ТОЛЬКО у себя: `dev/mobile-menu.pug` не делает
`extends ../../layout/main.pug`, а собирает свой минимальный `doctype html` (только
`include ../../layout/include.pug` для bemto/mixin-wrap + свой `_mobileMenu.pug`) с
`base(href="/")` в `<head>` — это чинит и CSS-ссылки, и относительные `img/...`/
`img/svg/sprite.svg#...` пути внутри самого блока (те же, что использует весь остальной
проект, менять их в `_mobileMenu.pug` ради одной dev-страницы неправильно). Если у других
блоков есть похожие `dev/*`-стенды — они словят точно этот же баг.

**Проверено:** без `base(href="/")` — 8 сетевых 404 (CSS + все картинки блока) при
полностью «зелёном» JS (никаких `pageerror`). С `base(href="/")` — 1 оставшийся 404,
`fonts/Vetrino-Regular.woff2` (см. п.4, не мой файл и не моя грабля).

## 3. Найденный (не мой) баг в других файлах: `npm run build` красный из-за чужих страниц

0 ошибок, отдельно проверено. Оставляю на усмотрение координатора/владельцев этих блоков.

## 6. Доступность — что сделано и как проверено

- `role="dialog"` + `aria-modal="true"` на контейнере, `aria-expanded` на всех
  `[data-mobile-menu-toggle]` и на всех триггерах drill-down (`[data-menu-open]`),
  синхронизируется в `mobile-menu.js` при каждом переключении экрана.
- Фокус-ловушка: не отдельный JS-трэп на подэкран, а следствие архитектуры — скрытые экраны
  имеют нативный атрибут `[hidden]`, который сам исключает их содержимое из таб-порядка и
  a11y-дерева; `Tab`/`Shift+Tab` внутри видимого экрана оборачиваются вручную
  (`trapFocus()` в `mobile-menu.js`), проверено Playwright-скриптом (см. п.7).
- `Escape` закрывает меню целиком и возвращает фокус на элемент, с которого меню было
  открыто (`lastFocused`).
- Скролл `body`/`html` блокируется классом `.mobileMenu-scroll-lock` с компенсацией
  `padding-right` по факту измеренной ширины скроллбара — без сдвига контента (грабля §4 ТЗ).

## 7. Как проверялось (интерактив, не только вёрстка)

`npm run build` (кроме чужих ошибок из п.3) → `npm run lint` → `npm test` — все exit 0 по
моим файлам. Отдельно: Playwright-скрипт (`chromium`, viewport 375×800,
`http-server public -p 5213`) — слушал `pageerror`/`console`: `pageerror` пусто на всех
прогонах; клик по триггеру открывает меню (класс/атрибут `[hidden]` меняется И элемент
реально `isVisible()`); тап по категории «Купальники» уводит на уровень 2 (root получает
`hidden`, `catalog-swimwear` — нет); «Назад» возвращает; тап «Для вас» уводит на клиентский
экран; `Escape` закрывает и сбрасывает `aria-expanded`; фокус не уходит за пределы меню на
`Shift+Tab`; горизонтального оверфлоу на 375 нет. Скриншоты всех трёх экранов сверены
глазами с `mcp__claude_ai_Figma__get_screenshot` по нодам `777:2`/`777:1466`/`777:1584` —
расхождений в структуре, порядке блоков и содержимом (кроме описанных в п.5 mock-компромиссов)
не найдено.
