   на
   ```pug

   ```
   (в блок `include`) и `+sStory()` на месте TODO в `block pagecontent`
   (после `+sTransformIntro()`, до `+sExpertise()` — таков порядок в `PLAN.md` §3).

2. **`source/js/story-compare.js` нужно подключить в `js-css.pug` (`+allcjs()`)**
   для продакшена. Сейчас скрипт грузится только на моей dev-странице через
   собственный `block scripts`. Файл — plain classic script (без `import`/
   `export`, тот же стиль что `common.js`), подключать обычным
   `script(src="js/story-compare.js")` рядом с `common.js`. common.js трогать
   не пришлось: он уже инициализирует ЛЮБОЙ `[data-swiper-options]` сам
   (`initDataSwipers()`), моя разметка этим воспользовалась без правок общего файла.

3. **Баг общего компонента `icon.pug` (не мой файл, нашёл по факту)** —
   `mixin icon(name, mod)` не форвардит `&attributes(attributes)`, поэтому
   цепочка классов вида `+icon('x').some-class` молча теряет `some-class`
   (проверено на собранном `public/index.html`: `+icon(iconName).eb-btn__icon`
   в `eb-ui.pug` тоже страдает тем же дефектом — итоговый `<svg>` не получает
   `eb-btn__icon`, только `icon icon-arrow-right`). Сам компонент не трогал
   (вне моей зоны). В своём блоке обошёл, передавая класс вторым параметром
   `mod`, как и задумано сигнатурой: `+icon('move-horizontal',
   'sStory__handle-icon')`. Стоит проверить остальные блоки, использующие
   `+icon(name).class`-цепочку — там же тот же незаметный баг (класс есть в
   Pug, в DOM его нет).

## Грабля, пойманная в процессе (для каталога `~/.claude/verstka-delivery.md` §6)

**`aspect-ratio` на родителе не считается «явной» высотой для растяжения
абсолютно спозиционированного потомка через `top:0;bottom:0` ИЛИ
`height:100%` — но конкретно у меня причина была ДРУГАЯ и более банальная.**

Ручка компаратора (`.sStory__handle`, `position:absolute; top:0; height:100%`)
схлопывалась до высоты своей кнопки (56px) вместо полной высоты фото-бокса
(960px/275px). Ушёл по ложному следу: сначала подозревал именно связку
`aspect-ratio` + абсолютно спозиционированный потомок (нашёл косвенное
подтверждение через `WebSearch`, что такая связка исторически проблемна) и
заменил `aspect-ratio` на классический приём `padding-bottom` — само по себе
не вредно, но **не было настоящей причиной**.

**Настоящая причина**: в `@include media-breakpoint-up(xl)` у меня был
скопипащен блок
```scss
&__handle,
&__handle-btn {
	width: rem(56);
	height: rem(56);
}
```
предназначенный только для `&__handle-btn` (кнопке ДЕЙСТВИТЕЛЬНО нужен
фиксированный размер), но `&__handle` (обёртка ручки, которая обязана
растягиваться на всю высоту фото) через запятую попал в тот же селектор и
получил `height: rem(56)` — что перебивало базовое `height:100%` того же
элемента на брейкпоинте ≥1200px (та же специфичность, более поздняя рулза
в каскаде побеждает). Ловилось только числовым замером
(`getBoundingClientRect().height`) — на глаз/скриншоте на десктопе тоже было
видно (кружок у самого верха фото), но причину нашёл только через
`getComputedStyle` + построчное сравнение инлайн-переопределений со
стилевым правилом.

**Урок**: при копировании `.sStory__selectorA, .sStory__selectorB { ... }` в
media-query-оверрайд — проверять, что оба селектора РЕАЛЬНО должны получить
ОБА свойства, а не «этому нужно только одно, а другому только другое, но
писать быстрее одним блоком». Убрал блок целиком — он был полностью избыточен
(both `&__handle` и `&__handle-btn` уже получают свои 56px в базовых, не
брейкпоинт-зависимых, правилах).

## Компромиссы / отклонения от буквального макета

- **Опечатка Figma исправлена в контенте**: узел `217:326`/`710:2085` называет
  заголовок «Результат после **подобра**» — очевидная опечатка дизайнера,
  в `sStory.json` записано «Результат после **подбора**».
- **Второй слайд — временная заглушка** (тот же приём, что уже принят у
  `sExpertise`): в Figma всего одна история («Виктория»), для проверки
  Swiper-механики (`loop`, стрелки, буллеты) на ≥2 слайдах добавил вторую
  запись «Александра» в `sStory.json`, переиспользуя те же фото/аватар.
  Помечено `_note` в JSON — заменить на реальный кейс, когда появится.
- **Токены типографики info/quote** не совпадают 1:1 с мобильной Figma-спекой:
  Figma даёт Body=18/Body[Mobile]=14 для строк параметров и цитаты, в проекте
  нет токена с такой лестницей (`--eb-body` идёт 16→17→18, `--eb-caption` —
  14→15→16). Взял `var(--eb-body)` везде — ближе к десктопному значению,
  отклонение на мобile ±2px, не хардкодил произвольное число.
- **Стрелки/буллеты `+ebSliderNav()` не имеют мобильного оверрайда 44px**
  (в Figma мобильные стрелки 44×44, десктопные и наши — 52×52 через
  `--eb-control-size`). Тот же компромисс уже задокументирован в
  `docs/coordination/sExpertise.md` — не стал делать точечный override под
  блок, чтобы не плодить локальные копии общего токена.
- **Grid-раскладка карточки на десктопе** — вместо буквального повторения
  Figma-геометрии (абсолютные `top`/`left` каждого элемента) использован
  `display:grid` с `grid-template-areas` + `display:contents` на
  `.sStory__card` (промотирует его детей в грид-ячейки). Ряд `result`
  получает `1fr`, что и создаёт визуальный «большой отступ» перед пагинацией
  в Figma — без магических пиксельных отступов.
- **Drag только за ручку**, не за произвольную точку фото (в макете
  показана именно ручка) — click/drag по остальной части фото не двигает
  границу. Дополнительно на ручке работает клавиатура (`ArrowLeft/Right`,
  `Home/End`) — это не было в макете явно, добавил для a11y (`role="slider"`).

### Playwright (десктоп 1920 и мобилка 375, dev-страница)

- Оверфлоу по горизонтали — нет ни на одной ширине.
- Все `<img>` в блоке — `naturalWidth > 0` (декодированы).
- Иконка `move-horizontal` — `stroke: rgb(44,43,43)` (`var(--eb-text)`), `fill: none` — контур реально виден, не «есть в DOM, но невидимо».
- **Замер компаратора** (программный drag мышью от ручки к 80% ширины бокса):
  `--split` до перетаскивания `30%` → после `~80%` (1920: `80%` точно, 375:
  `79.999...%`), `aria-valuenow` синхронно обновился до `80`. Число
  подтверждает, что граница реально сдвинулась, а не «визуально показалось».
- Клик по `.swiper-button-next` меняет `swiper.realIndex` с `0` на `1` на
  обеих ширинах.
- Ручка вертикально отцентрована и растянута на всю высоту фото-бокса на
  обеих ширинах (числом: центр кнопки == центр компаратора по вертикали;
  подробности бага и фикса — в разделе про граблю выше).
