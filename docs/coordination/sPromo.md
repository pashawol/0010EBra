# sPromo — координация

Блок «Акции» (node `385:1516` desktop 1790×1490 / мобильные баннеры `726:433`
внутри `692:1129`, файл `Wu9ocMTTTZvyFYbVm9Pz2D`). Три карточки-баннера:
«Комплект недели» (До 20%), «Подарок», «Outlet» (До 40%).

## Заявка: общий `+ebBanner`

Карточка-баннер — тот же компонент Figma `Banner` (`669:3449`, `669:3523`),
что уже свёрстан в `sGifts` (`.sGifts__card`). Структура и именование
элементов здесь **намеренно совпадают** со sGifts (`__card`, `__card-img`,
`-badge`), чтобы координатору было проще свести оба в один атом:

- `.sPromo__card` (`position:relative; overflow:hidden; border-radius:var(--eb-radius)`)
  → `<img class="__card-img">` (`object-fit:cover`, абсолютный) →
  опциональный бейдж (`__card-badge`) → `__card-body` (заголовок + текст).
- Тема карточки — классом `.eb-theme--dark` **на самой карточке** (прецедент
  `sGifts--cert`, `sExpertise`), не на секции.

**Отличия от sGifts, которые нужно учесть при обобщении:**

1. У sGifts подпись — один `<span class="card-caption">`. У sPromo подпись
   богаче: опциональный двухтоновый бейдж (иконка + белая пилюля с текстом)
   и заголовок из двух частей (`lead` — «До», `value` — «20%»/«40%»/«Подарок»).
   Предлагаемая сигнатура:
   ```pug
   mixin ebBanner(image, mod, opts)
     +b.eb-banner(class="--" + mod)&attributes(attributes)
       +img(image).eb-banner__img
       if opts.badge
         +ebBannerBadge(opts.badge).eb-banner__badge
       +e.DIV.eb-banner__body
         if opts.caption
           +e.SPAN.caption!= opts.caption
         else
           +e.DIV.title
             if opts.title.lead
               +e.SPAN.title-lead= opts.title.lead
             +e.SPAN.title-value= opts.title.value
           +e.P.text= opts.text
   ```
   т.е. `caption` (простой режим sGifts) ИЛИ `title+text` (режим sPromo) —
   разные потребители, один атом.
2. Бейдж (иконка + белая пилюля) в макете использован ТОЛЬКО в sPromo — в
   sGifts его нет. Иконки бейджей (`award`/`gift`/`percent`, Streamline-Lucide)
   **не заведены в общий svg-спрайт** (`source/svg/*` — вне зоны блока), в
   спрайте таких иконок пока нет вовсе. Инлайню их прямо в `_sPromo.pug` как
   raw `<svg><path stroke="currentColor">` — три места использования, не
   через глобальный `+icon()`. Если координатор решит их использовать где-то
   ещё — стоит добавить в `source/svg/` и завести обычным `+icon()`.
3. Высота карточки: в sGifts — три РАЗНЫЕ фикс-высоты (740/560/460) на
   lg+. В sPromo — у всех трёх карточек **одинаковая высота `rem(740)`**
   (верхняя на всю ширину, нижние две по 890px в ряд, `740+10+740=1490`
   сходится с высотой секции). Модификатор высоты в общем атоме нужен
   per-instance (rem-значение параметром), не хардкодиться в компоненте.
4. Позиция бейджа отличается по карточкам: у «week»/«gift» бейдж — абсолютный
   слой поверх фото (левый верхний угол); у «outlet» бейдж лежит **внутри**
   frosted-панели (в потоке, прижат к низу). В моей вёрстке это флаг
   `card.badgeInBody` — пригодится и в общем атоме.

## Тема карточек — по факту скриншота, не по формулировке брифа

Бриф описывал «outlet» как тёмную карточку. Проверил
`get_design_context(384:1409)` и скриншотом — визуально это **не** тот же
тёмный паттерн, что у «week» (бордовый фон, белый текст): «outlet» и «gift» —
фото + белая frosted-панель (`background: var(--eb-white-15)` +
`backdrop-filter: blur(var(--eb-blur))` у outlet, scrim-градиент у gift),
текст в обоих случаях `#2c2b2b` (`var(--eb-ink)`, дефолтная роль без
`.eb-theme--dark`). Тёмная (`.eb-theme--dark`, бордовое фото, белый текст) —
только верхняя карточка «week» («До 20%»). Задокументировано по правилу
«не подтверждай число/формулировку пользователя, пока не сверил с
источником» — сверил через Figma, поправил.

## Компромисс: цвет иконки бейджа

Иконка внутри translucent-пилюли не унифицирована в макете: на «week»/«gift»
(бейдж лежит поверх фото) — светлая, на «outlet» (бейдж внутри уже светлой
frosted-панели) — тёмная. В `_sPromo.scss` бейдж по умолчанию
`color: var(--eb-white)`, модификатор `&--outlet .sPromo__card-badge`
переопределяет на `var(--eb-ink)`. Оба — токены, не хардкод.

## Компромисс: `385:1481` («Sale», Брафиттинг +10%) — НЕ реализован

В задании этот node был указан как «плюс» к `385:1516`. Проверил
`get_metadata`/`get_design_context(385:1481)`: контент этого фрейма —
«Брафиттинг + / 10% на первую покупку / Запишитесь на брафиттинг, чтобы
получить скидку / [Записаться]» — **не совпадает** ни с одной из трёх карточек
акций, описанных в задании (20%/Подарок/40%). По контенту он гораздо ближе к
`sBooking` (форма записи на брафиттинг, `497:931`) либо к отдельному тизеру
рядом с ней. Мобильный аналог найден отдельно — `726:251` «Sale» (375-контекст,
y=7045, тоже «Брафиттинг + 10%»), физически ВНЕ `726:433` «Banners» (мобильных
карточек акций, y=7397) — то есть это независимый блок и на мобильной
странице тоже. Раз содержимое не подтверждено заданием и это, по всем
признакам, чужая секция (вероятно `sBooking` или отдельный блок между
`sQuiz`/`sPromo`), я его **не сверстал**, чтобы не задублировать чужую работу
и не выйти за границы. Если он всё же должен быть частью `sPromo` —
нужно отдельное решение координатора с указанием, куда он встаёт
(4-я карточка? отдельная секция?).

## Грабля, пойманная и исправленная в процессе: экспорт Figma-ассета с запечённым текстом

При первой попытке взял фон карточек через `download_assets` →
`export` (полный рендер узла `Banner`, т.е. фото + текстовые слои,
запечённые в один PNG). В браузере поверх этого PNG рендерился ещё и
**мой собственный** live-HTML текст (бейдж/заголовок/подпись) — визуально
это выглядело как «двоение» текста (два бейджа, два заголовка, слегка
смещённые). На скриншотах это сначала было принято за возможный баг
рендеринга Chromium/Playwright (проверил: не зависит от headless/headed,
GPU on/off, backdrop-filter, JS on/off — воспроизводилось везде, значит не
баг тулинга). DOM-проверкой (`querySelectorAll` + `getBoundingClientRect`)
подтверждено, что в разметке ровно один узел на каждый текстовый элемент —
значит «двойник» рисуется не HTML/CSS, а **самим PNG**. Пересобрал фон из
`rawImages` (сырые фото-филлы без текстовых слоёв Figma) — двоение исчезло
полностью. **Урок:** для фото-бэкграундов, где узел Figma — целый компонент
с текстом поверх фото (а не голый image-fill), брать из `download_assets`
именно `rawImages`, а не `export` — `export` рендерит весь узел целиком,
включая текст, который потом задвоится с вашей собственной вёрсткой этого
текста. Стоит вынести этот урок в `~/.claude/lessons/frontend.md` (не мой
файл — заявка координатору).

## Геометрия (desktop, lg+)

`.sPromo__grid` — колонка, `row--top` (баннер «week» на всю ширину) +
`row--bottom` (flex-row, `gift`+`outlet` по `flex:1 0 0`, грабля из плана —
значение `flex:1 0 0` только внутри `media-breakpoint-up(lg)`, на мобилке
карточки в столбец, высота по контенту через `aspect-ratio:345/275`).
Высота всех карточек на lg+ — фикс `rem(740)` (верх+низ+gap 10 = 1490,
сходится с высотой секции). Панель `outlet` на lg+ — фикс `rem(320)`
шириной, на мобилке — на всю ширину карточки.
