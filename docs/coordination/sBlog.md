# sBlog — координация

Блок «Блог Esthetic Bra» (node `495:202` desktop / `692:1129` → `737:707` mobile, файл `Wu9ocMTTTZvyFYbVm9Pz2D`).

## БЛОКИРУЮЩИЙ баг в общем `eb-ui.pug` (не трогал, только диагностировал)

`+ebBtn` и `+ebIconBtn` рендерят **дублированный класс** `eb-btn`/`eb-icon-btn` —
`html-validate` (`no-dup-class`) падает на любой странице, где они вызваны.
Воспроизводится минимальным вызовом, без какого-либо внешнего чейнинга:

```pug
+ebBtn('Все статьи', 'primary')
```

```html
<button class="eb-btn eb-btn eb-btn--primary" type="button">…</button>
```

**Причина.** В `eb-ui.pug` эти миксины смешивают два разных способа задать
BEM-класс на одном теге:

```pug
+b.BUTTON.eb-btn(class="eb-btn--" + mode type="button")
```

Точечная запись `.eb-btn` даёт bemto базовый класс. Но `class="eb-btn--" + mode`
bemto **тоже парсит** (regex на `--` внутри строки) и находит в
`"eb-btn--primary"` пару «база `eb-btn` + модификатор `primary`» — то есть
воссоздаёт базовый класс `eb-btn` ещё раз, независимо от точечной записи.
Итог — два источника одного и того же базового класса на одном теге.

Тот же паттерн в `ebIconBtn` ломает `sExpertise` (`eb-icon-btn` дублируется
там же, при вызове `+ebIconBtn(...)` — я не трогал этот блок, только увидел
в логе `npm run build` при параллельном прогоне).

**Предлагаемый фикс** (в `eb-ui.pug`, координатору): убрать точечный класс и
отдать BEM-сборку целиком bemto — модификатор уже содержит имя базового
класса:

```pug
mixin ebBtn(text, mode, iconName)
	- mode = mode || 'primary'
	+b.BUTTON(class="eb-btn eb-btn--" + mode type="button")&attributes(attributes)
```

либо наоборot — убрать `class="eb-btn--" + mode` и передавать модификатор
через `&attributes` со своим `class`, но не смешивать точечную запись с
ручной `--`-строкой на одном теге. Аналогично для `ebIconBtn`.

**Как повлияло на мой блок.** `dev-sBlog.html` — единственная ошибка
`html-validate` в моём файле — этот дубль на кнопке «Все статьи»
(`+ebBtn(data.cta.text, 'primary')`). Весь остальной DOM блока (3
`<article>`, `<time>`, теги категорий, картинки) проходит validate чисто.
Я не правил `eb-ui.pug` (правило изоляции), поэтому `npm run build` у меня
красный из-за этого одного дефекта в общем файле — не из-за кода `sBlog`.

## Заявка: вынести `+ebArticleCard` в общий `eb-ui`

Собрал карточку статьи локально в `source/pug/blocks/sBlog/_sBlog.pug` +
`_sBlog.scss` (мixin `ebArticleCard`, класс `.eb-article-card`) — это и есть
компонент `article` из UI-Kit (`669:3563`), который по `docs/PLAN.md` §3.1
понадобится ещё как минимум `sFavorites`/`sBestSets`-соседям (общая карточка
товара уже выносится отдельно, но `article`-карточка блога — свой тип).

Параметры, что должны попасть в общий компонент:
- `article.image`, `article.imageAlt`, `article.title`, `article.text`,
  `article.category`, `article.date` (ISO), `article.dateLabel`, `article.href`.
- Модификатор ширины/пропорции фото — в моей версии это отдельный
  CSS-модификатор `.sBlog__article--feat` (60/40 split, фото 810×460) против
  обычной карточки (40/60 split, фото 360×460) через custom-property
  `--card-image-ratio`. Общий компонент, видимо, должен принимать это как
  параметр (`size: 'featured' | 'default'`), а не через blок-специфичный
  класс.
- Мобильный layout — `flex-direction: column`, картинка full-width,
  `aspect-ratio: 345/185` (другое соотношение, чем у десктопных карточек!) —
  переключение на `flex-direction: row` только с `lg`.
- Клик по всей карточке — через `::after` на ссылке в заголовке (не на
  `<article>` целиком и не отдельным `<a>`-оверлеем), чтоббы не плодить
  дублирующиеся ссылки для скринридеров.
- Описание — `line-clamp: 3` (переменной длины текст не должен разъезжать
  карточки по высоте, см. §3.1 «граблю»).

Как только координатор вынесет `+ebArticleCard`/`.eb-article-card` в
`eb-ui.pug`/`eb-ui.scss`, `_sBlog.scss` можно сократить — оставить только
модификаторы `--feat`/`--a`/`--b` (grid-area) и убрать копию базового
компонента.

## Раскладка: почему `grid-template-areas`, а не flex/nth-child

Мобильный `692:1129 → 737:707` и десктопный `495:202` показывают **разный
порядок** карточек: на мобиле кнопка «Все статьи» стоит **в самом низу**,
после всех трёх карточек, а на десктопе — сразу под заголовком. Пробовать
решить это через DOM-порядок + `flex-wrap`/`order` на плоском списке не
вышло бы без создания искусственных оберток, которые в свою очередь ломают
десктопную сетку (там колонки другой ширины — 1:3 у верхней строки, 1:1 у
нижней, что не сочетается с одним набором flex-basis).

Решение: один DOM-порядок (title → cta → feat → a → b), 4-колоночный CSS
Grid, `grid-template-areas` разный на мобиле и от `lg` — карточка находит
свою ячейку по имени модификатора (`sBlog__article--feat/a/b`), без
привязки к порядку в разметке. Проверено на 375/768/1280/1920 — острова не
съезжают, порядок на каждой ширине соответствует своей ноде figma.

## Компромиссы

- Кнопка «Все статьи» — `<button type="button">` (это то, что рендерит
  `+ebBtn`), не `<a href="#">`. Инструкция требовала переиспользовать
  `+ebBtn`, а он не умеет рендериться якорем. Функционально не критично
  (проект — «только вёрстка», без реальной навигации), но семантически
  кнопка «Все статьи» — это переход на страницу, а не действие. Если
  понадобится настоящая ссылка — координатору стоит завести
  `ebBtn(..., { as: 'a', href })` или `ebBtnLink`.
- Заголовки карточек — `<h3>` (после `<h2>` секции, без пропуска уровня),
  но кегль — `var(--eb-h4)` через явный override в `.eb-article-card__title`
  (глобальный `h3` дал бы 54/40/28px — визуально спорит с заголовком секции
  и не помещается в 470px колонку по 3 строки, как в макете).
- Брейкпоинт переключения раскладки — `lg` (992px), как у `sTransformIntro`.
  На 768 (тестовая ширина DoD) карточки идут в мобильной колонке — так и
  задумано, отдельного «промежуточного» состояния для планшета в макете нет
  (§9 плана: «Планшет не нарисован»).
